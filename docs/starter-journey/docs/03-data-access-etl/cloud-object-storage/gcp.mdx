# GCP GCS

> **You'll create** a Unity Catalog storage credential (a GCP service account Databricks manages for you), grant that service account access to a GCS bucket, then create an external location that points Databricks at it in ~10 min. Need file events? Add the optional part. Need a bucket first? See the [bonus at the end](#bonus-create-a-gcs-bucket).
>
> **Prereqs:** [Cloud Object Storage overview](/docs/03-data-access-etl/cloud-object-storage), a GCP project with permission to grant IAM roles on the bucket, and a Databricks metastore admin or account admin

## Existing or new bucket

Unity Catalog reaches Google Cloud Storage through an **external location** — a named object that points at a `gs://` path through a storage credential (a GCP service account Databricks authenticates as). There are two reasons to create one:

- **Access an existing GCS bucket with data.** When a bucket already holds data, point an external location at it so Unity Catalog can read (and optionally write) that data in place — usually to ingest it into Databricks. Mark the location read-only if you only need to read from it.
- **Use a new bucket for Unity Catalog managed data.** Create a fresh GCS bucket for Unity Catalog to store managed tables and volumes, then point an external location (or a catalog's managed storage) at it.

Either way, the setup below is the same. This page assumes the bucket already exists; if it doesn't, create one first with the [bonus](#bonus-create-a-gcs-bucket).

## The big picture

A GCS bucket Databricks reaches through a Unity Catalog storage credential and external location. Unlike AWS, you don't approve an automatic role hand-off: Databricks generates a **GCP service account** when you create the storage credential, and you grant that service account access to the bucket in the Google Cloud console. If you want [file events](#enable-file-events-optional), you also create a custom Pub/Sub role and let the Cloud Storage service agent publish notifications.

## Permissions you need

Check these before you start.

### GCP

- Ability to sign in to the GCP project that owns the bucket and grant IAM roles on the bucket (for example **Storage Admin** or **Owner**). Granting roles on the bucket is what lets Databricks' service account read and write.
- To enable file events, you also need permission to create a custom IAM role and grant project-level roles (**Owner** or **IAM Admin**).

### Databricks

You need these Unity Catalog privileges. Metastore admins and account admins already have them. Workspace admin is not enough on its own.

| Privilege | On | Why you need it |
|---|---|---|
| `CREATE STORAGE CREDENTIAL` | Metastore | Create the credential that wraps the GCP service account. |
| `CREATE EXTERNAL LOCATION` | Metastore | Create the path object. |

If you are not a metastore admin, ask one to grant your group:

```sql
GRANT CREATE STORAGE CREDENTIAL, CREATE EXTERNAL LOCATION ON METASTORE TO `your-group`;
```

## Create a storage credential

The storage credential is the Unity Catalog object that holds a Databricks-managed GCP service account. Create it first, because you grant that service account access to the bucket in the next section.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step001.png" alt="Catalog page with the Create menu open and Create a credential highlighted" />

</Step>

## Grant the service account access to the bucket

The service account has no access to the bucket yet. Grant it two roles on the bucket in the Google Cloud console — **Storage Legacy Bucket Reader** (list the bucket) and **Storage Object Admin** (read and write objects) — or the connection test at the end fails.

<StepGuide
  description="Grant the credential's service account Storage Legacy Bucket Reader and Storage Object Admin on the GCS bucket."
  minutes={4}
  idPrefix="bucket-iam-step"
  referenceHref="https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/external-locations-gcs"
  referenceLabel="Connect to GCS external locations (Databricks docs)">

<Step>

In the [Google Cloud console](https://console.cloud.google.com/), open the bucket in **Cloud Storage** > **Buckets**, then open its **Permissions** tab.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step004.png" alt="GCS bucket details with the Permissions tab" />

</Step>

<Step>

Under **Permissions**, click **Grant access**, then paste the service account email you copied from Databricks into **New principals**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step005.png" alt="Bucket Permissions section with the Grant access button" />

</Step>

<Step>

Under **Assign roles**, open **Select a role** and choose **Storage Legacy Bucket Reader**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step006.png" alt="Assign roles with the role dropdown open and Storage Legacy Bucket Reader selected" />

</Step>

<Step>

With **Storage Legacy Bucket Reader** set, click **Add another role**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step007.png" alt="Assign roles showing Storage Legacy Bucket Reader with Add another role" />

</Step>

<Step>

Open the second **Select a role** dropdown.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step008.png" alt="Second Select a role dropdown for the additional role" />

</Step>

<Step>

Search for **storage** and select **Storage Object Admin**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step009.png" alt="Role search showing Storage Object Admin" />

</Step>

<Step>

Confirm the service account is the principal and both **Storage Legacy Bucket Reader** and **Storage Object Admin** are assigned, then click **Save**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step010.png" alt="Grant access form with both roles assigned and the Save button" />

</Step>

</StepGuide>

## Enable file events (optional)

:::note
This part is **optional**. File events let Unity Catalog use bucket notifications (for example, for Auto Loader file notification mode and managed ingestion) instead of listing the bucket. Skip it if you only need to read and write the location. You can add it later.
:::

File events need two grants: a **custom Pub/Sub role** on the credential's service account (so Databricks can manage the topic and subscription), and the **Pub/Sub Publisher** role on the project's **Cloud Storage service agent** (so GCS can publish object notifications).

<StepGuide
  description="Create a custom Pub/Sub role, grant it to the credential service account, and let the Cloud Storage service agent publish notifications."
  minutes={8}
  idPrefix="file-events-step"
  referenceHref="https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/manage-external-locations#file-events"
  referenceLabel="Enable file events (Databricks docs)">

<Step>

In the Google Cloud console, search for and open **IAM & Admin** > **IAM**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step011.png" alt="Google Cloud console search for IAM & Admin" />

</Step>

<Step>

Go to **Roles** and click **Create custom role**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step012.png" alt="IAM & Admin Roles page with Create custom role" />

</Step>

<Step>

Give the role a **title** (for example `starterjourney-file-events`) and **ID**, then click **Add permissions**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step013.png" alt="Create role page with title, ID, and Add permissions" />

</Step>

<Step>

Add these permissions, click **Add**, then **Create** the role:

```
pubsub.subscriptions.consume
pubsub.subscriptions.create
pubsub.subscriptions.delete
pubsub.subscriptions.get
pubsub.subscriptions.list
pubsub.subscriptions.update
pubsub.topics.attachSubscription
pubsub.topics.detachSubscription
pubsub.topics.create
pubsub.topics.delete
pubsub.topics.get
pubsub.topics.list
pubsub.topics.update
storage.buckets.update
```

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step014.png" alt="Add permissions dialog with pubsub and storage permissions selected" />

</Step>

<Step>

Back on **IAM**, click **Grant access**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step015.png" alt="IAM page with Grant access" />

</Step>

<Step>

In **New principals**, paste the credential's service account email (the `db-uc-credential-` one). In **Assign roles**, select the custom role you just created, then click **Save**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step016.png" alt="Grant access panel assigning the custom file-events role to the credential service account" />

</Step>

<Step>

Now find the project's **Cloud Storage service agent** — a Google-managed account that publishes notifications. See the Google guide, [Get the Cloud Storage service agent](https://cloud.google.com/storage/docs/getting-service-agent).

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step017.png" alt="Google docs page describing how to get the Cloud Storage service agent" />

</Step>

<Step>

In **Cloud Storage** > **Settings**, copy the **Cloud Storage Service Account** email.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step018.png" alt="Cloud Storage Settings page with the Cloud Storage Service Account to copy" />

</Step>

<Step>

Back on **IAM**, click **Grant access** again.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step019.png" alt="IAM page with Grant access for the service agent" />

</Step>

<Step>

Paste the Cloud Storage service agent email into **New principals**, assign the **Pub/Sub Publisher** role, then click **Save**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step020.png" alt="Grant access panel assigning Pub/Sub Publisher to the Cloud Storage service agent" />

</Step>

</StepGuide>

## Create an external location

The external location is the Unity Catalog object that points at the GCS bucket path through the storage credential you created.

<StepGuide
  description="Create an external location that points at the GCS path through your storage credential."
  minutes={3}
  idPrefix="external-location-step"
  referenceHref="https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/external-locations"
  referenceLabel="Create an external location (Databricks docs)">

<Step>

In the Databricks workspace, click **Catalog**, then click **Create** > **Create an external location**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step021.png" alt="Catalog page with the Create menu open and Create an external location highlighted" />

</Step>

<Step>

Fill in the form:
- **External location name:** a descriptive name (for example `starterjourneyextloc`).
- **Storage type:** GCP.
- **URL:** the bucket path, `gs://<bucket-name>/<directory>` (for example `gs://starterjourney/unitycatalog`).
- **Storage credential:** the credential you created earlier.

Click **Create**.

<StepImage src="/img/gcp/gcp_ext_loc_creation/gcp_external_location_Step022.png" alt="Create a new external location form with name, GCP storage type, URL, and storage credential" />

</Step>

</StepGuide>

:::tip
If this location holds source data you only read from, mark it read-only afterward so a stray job cannot overwrite it. Follow [Mark an external location as read-only](https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/manage-external-locations#mark-an-external-location-as-read-only).
:::

## Where people trip

<details>
<summary>Test connection fails with permission denied</summary>

The service account behind the storage credential is missing a role on the bucket. Confirm both **Storage Legacy Bucket Reader** and **Storage Object Admin** are granted to the `db-uc-credential-` service account on the bucket's Permissions tab, then test again.
</details>

<details>
<summary>External location creation fails with invalid URL</summary>

The URL has to be `gs://<bucket-name>/<directory>`. Confirm the bucket exists and the name is spelled correctly.
</details>

<details>
<summary>File events don't fire</summary>

File events need both grants: the custom Pub/Sub role on the credential's service account, and **Pub/Sub Publisher** on the project's Cloud Storage service agent. Re-check the [Enable file events](#enable-file-events-optional) grants — the service agent grant is the most common one to miss.
</details>

If you don't already have a GCS bucket, create one here first, then go back to [Create a storage credential](#create-a-storage-credential) and point the external location at the new bucket.

<StepGuide
  description="Create a GCS bucket to use as a landing zone or as Unity Catalog storage."

<StepImage src="/img/gcp/createbucket/gcp_bucket_creation_Step002.png" alt="Cloud Storage Buckets page with the Create button" />

<Step>

</Step>

<Step>
