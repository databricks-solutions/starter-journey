# Business semantics on Databricks

> **You'll** work through a **self-paced** path to **activate** Unity Catalog **business semantics** — metric views, governed definitions, and AI-ready metadata on the Databricks Data Intelligence Platform. Budget roughly **2–3 hours of reading** plus a **guided hands-on** block when you are ready to test in a workspace.
>
> **Prereqs:** [Unity Catalog foundations](/docs/before-you-start/foundations/unity-catalog), [Data governance strategy](/docs/data-governance-strategy/) — catalogs, permissions, and workspace access in place

## Why this section exists

KPIs break down when every team redefines the same number in a different way. Databricks unifies **definitions at the data layer** through Unity Catalog **metric views**, so SQL, notebooks, AI/BI, and natural-language experiences can use the same certified semantics — without re-implementing business logic on each surface.

This path is **self-paced** and product-focused: it is written for **customers and practitioners** who want to **turn on and adopt** these capabilities in a real Databricks account. It stays on the Databricks platform: governance, the lakehouse, and AI/BI (including Genie).

## Self-paced path overview

| Topic | Audience | Outcome |
| --- | --- | --- |

| [Metric views fundamentals](/docs/business-semantics/metric-views-fundamentals) | Data engineers and analysts | Recognize a metric view, its parts, and how to author one |
| [Data modeling for metric views](/docs/business-semantics/data-modeling-metric-views) | Data engineers | Model joins, composability, time patterns, and performance for production |
| [Agent metadata for AI readiness](/docs/business-semantics/agent-metadata-ai-readiness) | Data engineers and AI/data teams | Add metadata so natural-language and AI features pick the right metrics |
| [Technical enablement (hands-on)](/docs/business-semantics/technical-enablement-lab) | Data engineers (analysts optional) | **Activate** the full path: create, govern, and validate in SQL, AI/BI, and Genie |

**How to use it:** go in order, or open the **hands-on** last after the conceptual topics. Each page has a **topic checklist** you can work through at your own pace.

## Journey checklist (Business semantics)

Track your own progress in your workspace and with your stakeholders.

- [ ] [Why a semantic layer?](/docs/business-semantics/why-semantic-layer) — align on **metric drift** and why definitions belong in Unity Catalog
- [ ] [Metric views fundamentals](/docs/business-semantics/metric-views-fundamentals) — understand **measures, dimensions, filters** and **authoring** options (SQL, UI, YAML)
- [ ] [Data modeling for metric views](/docs/business-semantics/data-modeling-metric-views) — design **joins and sources**, **composability**, and **materialization** where it helps
- [ ] [Agent metadata for AI readiness](/docs/business-semantics/agent-metadata-ai-readiness) — set **synonyms, tags, instructions, certification** for **Genie** and other AI/BI
- [ ] [Technical enablement (hands-on)](/docs/business-semantics/technical-enablement-lab) — create **one** sales-style KPI, **publish** it, and **query** the same result from **SQL, notebook, AI/BI, Genie**
- [ ] (Optional) Roll the same pattern to the **next** KPIs your org cares about, using the same governance model

## Where this fits on the platform

**Business semantics** (metric views and related metadata) is part of the **Databricks Data Intelligence Platform**: your governed data in Unity Catalog, query engines, AI/BI, jobs and orchestration, and conversational analytics — all able to read the **same** metric definitions at the data layer.
