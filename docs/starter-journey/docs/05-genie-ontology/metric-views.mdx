# Metric Views

> **You'll define** a governed `franchise_sales_metrics` metric view and confirm it matches your section 8 query in ~20 min.
>
> **Prereqs:** [8. Query and Explore](/docs/03-data-access-etl/query-and-explore), a serverless SQL warehouse, CREATE privileges on the target schema

## The big picture

In section 8 you proved daily franchise revenue with one saved query. A metric view promotes that logic into a governed object: define Total Sales, Order Count, and Avg Order Value once, and every dashboard, Genie Agent, and SQL client reads the same definition. Change the number in one place and every consumer picks it up on the next query.

The source is your silver layer. The output is `starterjourney_catalog.bakehouse_gold.franchise_sales_metrics`.

## Build the metric view

  description="Create the gold schema, generate the metric view with Genie Code, then validate it against section 8."
  minutes={20}

<Step>

Create the destination schema if it does not exist yet. In a SQL editor on `starter_journey_wh`, run:

```sql
CREATE SCHEMA IF NOT EXISTS starterjourney_catalog.bakehouse_gold;
```

<StepImage src="/img/unified-metric-views/1.png" alt="SQL Editor running CREATE SCHEMA IF NOT EXISTS starterjourney_catalog.bakehouse_gold" />

</Step>

<Step>

In Catalog Explorer, open the `bakehouse_gold` schema and click **Create > Metric view** (or open SQL Editor).

<StepImage src="/img/unified-metric-views/2.png" alt="bakehouse_gold schema in Catalog Explorer with the Create menu open on Metric view" />

</Step>

<Step>

Enter the name `franchise_sales_metrics`, set the catalog to `starterjourney_catalog` and the schema to `bakehouse_gold`, then click **Create**.

<StepImage src="/img/unified-metric-views/3.png" alt="Create metric view dialog with name franchise_sales_metrics and location starterjourney_catalog.bakehouse_gold" />

</Step>

<Step>

In the editor, open **Genie Code** from the button in the upper-right corner. Paste this prompt:

<PromptBlock>
Create a metric view on starterjourney_catalog.bakehouse_silver.transactions joined to starterjourney_catalog.bakehouse_silver.franchises on franchise_id, many-to-one. Add fields: franchise (the franchise_name from the join), sales_date (the transaction_timestamp truncated to a day), and product. Add measures: total_sales as SUM(total_price), order_count as COUNT(1), and avg_order_value as total_sales divided by order_count. Add the synonyms "revenue" and "sales" to total_sales, and "AOV" to avg_order_value.
</PromptBlock>

<StepImage src="/img/unified-metric-views/4.png" alt="Metric view editor with the Genie Code panel and the franchise_sales_metrics prompt" />

</Step>

<Step>

Review the generated definition against this checklist:

- Source is `bakehouse_silver.transactions`, joined to `bakehouse_silver.franchises` on `franchise_id`, many-to-one.
- Fields: `franchise`, `sales_date` (day level), `product`.
- Measures: `total_sales` is `SUM(total_price)`, `order_count` is `COUNT(1)`, `avg_order_value` is `MEASURE(total_sales) / MEASURE(order_count)`.

<details>
<summary>Use the fallback YAML</summary>

Open the YAML editor with the `<>` button and replace the definition with:

```yaml
version: 1.1
comment: 'Franchise sales KPIs for the Bakehouse journey'
source: starterjourney_catalog.bakehouse_silver.transactions
joins:
  - name: franchise
    source: starterjourney_catalog.bakehouse_silver.franchises
    'on': source.franchise_id = franchise.franchise_id
    rely:
      at_most_one_match: true
fields:
  - name: franchise
    expr: franchise.franchise_name
    comment: 'Franchise name'
  - name: sales_date
    expr: DATE(source.transaction_timestamp)
    comment: 'Calendar day of the transaction'
  - name: product
    expr: source.product
    comment: 'Product sold'
measures:
  - name: total_sales
    expr: SUM(source.total_price)
    comment: 'Sum of transaction total price'
    synonyms: ['revenue', 'sales']
  - name: order_count
    expr: COUNT(1)
    comment: 'Number of transactions'
  - name: avg_order_value
    expr: MEASURE(total_sales) / MEASURE(order_count)
    comment: 'Average order value'
    synonyms: ['AOV']
```

</details>

<StepImage src="/img/unified-metric-views/5.png" alt="Genie Code generated join and measures with the Accept all button" />

</Step>

<Step>

Preview the fields and measures panel, then click **Save**.

<StepImage src="/img/unified-metric-views/6.png" alt="Metric view Overview showing three measures, three fields, and the preview panel" />

</Step>

<Step>

Validate against section 8. In a SQL editor, run:

```sql
SELECT
  `sales_date`,
  `franchise`,
  MEASURE(`total_sales`) AS total_sales
FROM starterjourney_catalog.bakehouse_gold.franchise_sales_metrics
GROUP BY ALL
ORDER BY `sales_date`, `franchise`;
```

The daily totals per franchise should match your `daily_franchise_revenue` query from section 8. If they don't, the join or a measure is off.

<StepImage src="/img/unified-metric-views/7.png" alt="SQL Editor running the MEASURE query on franchise_sales_metrics with Sales Date, Franchise, and Total Sales results" />

</Step>

</StepGuide>

## Where people trip

<details>
<summary>Create > Metric view is disabled</summary>

Metric views need compute on Databricks Runtime 17.3 or above. Attach a serverless warehouse or a 17.3+ cluster.
</details>

<details>
<summary>Totals look inflated</summary>

The join is fanning out rows. Confirm the franchise join is many-to-one on `franchise_id`, not one-to-many.
</details>

<details>
<summary>Genie Code used different field names</summary>

The field names feed the dashboard and Genie prompts on the next pages. Rename them to `franchise`, `sales_date`, `product`, `total_sales`, `order_count`, and `avg_order_value`, or paste the fallback YAML.
</details>

<details>
<summary>Daily totals don't match section 8</summary>

Check that `sales_date` truncates `transaction_timestamp` to a day and `total_sales` sums `total_price`. Reconcile any time zone difference.
</details>
