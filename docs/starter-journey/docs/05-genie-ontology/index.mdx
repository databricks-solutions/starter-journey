# 5. Genie Ontology

> **You'll understand** how Genie Ontology routes a broad business question to the right governed analytics surface in ~10 min.
>
> **Prereqs:** [Unity Catalog Setup](/docs/04-governance/unity-catalog-setup), [Build the first ETL pipeline](/docs/03-data-access-etl/build-first-pipeline/), [Query and explore](/docs/03-data-access-etl/query-and-explore)

Use an ontology when one broad question could belong to several dashboards or agents.
The ontology gives Genie a routing tree, so it can find the right governed surface instead of making the user choose one first.

```text
User question
  -> Domain
    -> optional Subdomain
      -> Page
        -> Dashboard or Genie Agent
```

Think of the domain as the front desk.
It reads the question, sends broad overview requests to a dashboard page, and sends detailed analysis to a page backed by a Genie Agent.

## The Bakehouse routing tree

The Bakehouse example uses one direct page for an executive overview and one subdomain for deeper questions:

```text
Domain: Bakehouse Sales Operations
├── Page: Franchise Performance at a Glance
│   └── Bakehouse Franchise Performance dashboard
└── Subdomain: Sales Analytics
    └── Page: Sales Q&A Assistant
        └── Bakehouse Sales Assistant Genie Agent
```

Questions that ask for an overview, snapshot, or visual comparison stop at the dashboard page.
Questions that ask for a ranking, a computed comparison, or analysis of a specific franchise continue into Sales Analytics and reach the Genie Agent.

Both surfaces use `starterjourney_catalog.bakehouse_gold.franchise_sales_metrics`.
That shared metric view keeps Total Sales, Order Count, and Avg Order Value consistent after the ontology chooses a destination.
