# GCP serverless workspace creation

> **You'll create** a serverless Databricks workspace on GCP in ~10 min.
>
> **Prereqs:** [GCP account](/docs/01-introduction/cloud-tenant-ready/single-tenant-setup), [Databricks account console](/docs/01-introduction/foundations/account-console)

## The big picture

A running Databricks workspace where Databricks manages the compute and the storage.
There is no VPC to size, no service account to wire up, and no cross-project trust to configure.
You turn on a preview, fill in a short dialog, grant Google account permissions, and the workspace comes up ready to use.
Start here for your first GCP workspace and for most new deployments.

## Prerequisites

- A Databricks account with account-admin privileges (GCP Marketplace subscription).
- A GCP region where serverless workspaces are available.
Deploy the workspace close to your data sources.

## Deploy with Terraform

You can create the same workspace as code.
A serverless workspace needs no VPC or service account, so the workspace resource is the only thing to declare.
Setting `compute_mode = "SERVERLESS"` is what makes it serverless.

```hcl title="main.tf"
terraform {
  required_providers {
    databricks = {
      source = "databricks/databricks"
    }
  }
}

variable "databricks_account_id" {
  description = "Account ID from the account console (top right, under your user name)"
}

provider "databricks" {
  host       = "https://accounts.gcp.databricks.com"
  account_id = var.databricks_account_id
}

resource "databricks_mws_workspaces" "this" {
  account_id     = var.databricks_account_id
  workspace_name = "serverless-workspace"
  location       = "us-east4"
  compute_mode   = "SERVERLESS"
}

output "workspace_url" {
  value = databricks_mws_workspaces.this.workspace_url
}
```

The provider talks to the account console, not a workspace.
Authenticate with an account-level service principal by exporting `DATABRICKS_CLIENT_ID` and `DATABRICKS_CLIENT_SECRET`, or with a Google service account through `google_service_account`.
See [provider authentication](https://registry.terraform.io/providers/databricks/databricks/latest/docs#authentication) for the details.

Then run:

```bash
terraform init
terraform plan -var="databricks_account_id=<your-account-id>"
terraform apply -var="databricks_account_id=<your-account-id>"
```

When the apply finishes, Terraform prints `workspace_url`.
Open it and you land on the same **Welcome to Databricks** page shown above.

## Where people trip

<details>
<summary>Terraform rejects credentials_id or storage_configuration_id</summary>

Serverless workspaces must not set `credentials_id` or `storage_configuration_id`.
Those belong to classic workspaces.
Remove both arguments and keep `compute_mode = "SERVERLESS"`.
</details>

<details>
<summary>Serverless Workspaces is not in the Previews list</summary>

The preview toggle only shows for account admins.
Confirm you have account-admin privileges on the account console.
If it is still missing, serverless workspaces may not be available yet in your account or region.
Check the [supported GCP regions](https://docs.databricks.com/gcp/en/resources/supported-regions) list.
</details>

<details>
<summary>Wrong Google account on the Allow step</summary>

The Google account you click **Allow** with must match the account linked to your Databricks account.
If you see a different account in the sign-in prompt, click **Use a different account** and sign in with the correct one.
Allowing with the wrong account causes permission errors when the workspace tries to access GCP resources.
</details>

<details>
<summary>Picked the wrong region</summary>

A workspace cannot move regions once created.
Delete the workspace and create a new one in the correct region.
Deploy in the region that hosts your data sources to avoid cross-region egress fees.
See [supported GCP regions](https://docs.databricks.com/gcp/en/resources/supported-regions) for the full list.
</details>
