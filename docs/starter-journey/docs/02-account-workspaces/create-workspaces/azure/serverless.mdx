# Azure serverless workspace creation

> **You'll create** a serverless Databricks workspace on Azure in ~10 min.
>
> **Prereqs:** [Azure account](/docs/01-introduction/cloud-tenant-ready/single-tenant-setup)

## The big picture

A running Databricks workspace where Databricks manages the compute and the storage.
There is no VNet to size, no IAM role to wire up, and no cross-subscription trust to configure.
You fill in a short form in the Azure portal, wait a few minutes, and the workspace comes up ready to use.
Start here for your first workspace on Azure and for most new serverless deployments.

## Prerequisites

- An Azure subscription with **Contributor** access at the subscription scope.
- A Databricks account with account-admin privileges.
- An Azure region where serverless workspaces are available.
Deploy the workspace close to your data sources.

<Step>

Fill in the workspace details on the **Basics** tab:

- **Subscription** - choose your Azure subscription.
- **Resource group** - choose an existing resource group or create a new one.
- **Workspace name** - provide a descriptive name. You cannot change this later.
- **Region** - choose the region to deploy into. Deploy close to your data sources.
- **Pricing Tier** - select **Premium**. Serverless requires Premium.
- **Workspace type** - select **Serverless**.
- Optionally add **Tags**.

Click **Review + create**.

## Deploy with Terraform

You can create the same workspace as code.
On Azure the workspace is an Azure resource, so you use Azure providers rather than the Databricks one.
Setting `computeMode = "Serverless"` with the Premium SKU is what makes it serverless.

:::warning
The `azurerm_databricks_workspace` resource cannot create serverless workspaces yet (tracked in [terraform-provider-azurerm#31218](https://github.com/hashicorp/terraform-provider-azurerm/issues/31218)).
The example below calls the Azure Databricks ARM API directly through the AzAPI provider.
:::

```hcl title="main.tf"
terraform {
  required_providers {
    azurerm = {
      source = "hashicorp/azurerm"
    }
    azapi = {
      source  = "Azure/azapi"
      version = ">= 2.0"
    }
  }
}

provider "azurerm" {
  features {}
}

provider "azapi" {}

resource "azurerm_resource_group" "this" {
  name     = "rg-databricks-serverless"
  location = "eastus"
}

resource "azapi_resource" "workspace" {
  type      = "Microsoft.Databricks/workspaces@2026-01-01"
  name      = "adb-serverless-ws"
  parent_id = azurerm_resource_group.this.id
  location  = azurerm_resource_group.this.location

  body = {
    sku = {
      name = "premium"
    }
    properties = {
      computeMode = "Serverless"
    }
  }

  response_export_values = ["properties.workspaceUrl"]
}

output "workspace_url" {
  value = "https://${azapi_resource.workspace.output.properties.workspaceUrl}"
}
```

Log in with `az login` (or set the `ARM_*` environment variables for a service principal), then run:

```bash
terraform init
terraform plan
terraform apply
```

When the apply finishes, Terraform prints `workspace_url`.
Open it and you land on the same **Welcome to Databricks** page shown above.

:::tip
For production, start from the SRA [serverless_workspace module](https://github.com/databricks/terraform-databricks-sra/tree/main/azure/tf/modules/serverless_workspace).
It adds metastore assignment, a network connectivity config, a network policy, customer-managed keys, and front-end Private Link on top of this example.
:::

## Where people trip

<details>
<summary>azurerm_databricks_workspace has no serverless option</summary>

The AzureRM resource cannot set `computeMode`, and that property can only be set at creation.
Use the `azapi_resource` example above instead.
Do not set a managed resource group, VNet parameters, or an access connector in the body: the API rejects them for serverless workspaces.
</details>

<details>
<summary>The Workspace type field does not show "Serverless"</summary>

Serverless workspace type only appears when **Premium** is selected as the Pricing Tier.
Switch the Pricing Tier to **Premium** first - the Workspace type dropdown then shows the Serverless option.
If Premium is not available in your subscription, contact your Azure account team.
</details>

<details>
<summary>Validation fails with a permissions error</summary>

Databricks creates a managed resource group during workspace deployment.
This requires **Contributor** access at the subscription scope, not just the resource group level.
Confirm your role assignment in the Azure portal under **Subscriptions > Access control (IAM)**.
</details>

<details>
<summary>Deployment completes but Launch Workspace shows an error</summary>

Give the workspace a minute after the Azure deployment finishes before clicking **Launch Workspace**.
If the error persists, open the Databricks account console at [accounts.azuredatabricks.net](https://accounts.azuredatabricks.net) and confirm the workspace shows **Running** there.
If it shows an error state, delete the workspace and redeploy.
</details>
