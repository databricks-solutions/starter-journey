# AWS serverless workspace creation

> **You'll create** a serverless Databricks workspace on AWS in ~10 min.
>
> **Prereqs:** [AWS account](/docs/01-introduction/cloud-tenant-ready/single-tenant-setup), [Databricks account console](/docs/01-introduction/foundations/account-console)

## The big picture

A running Databricks workspace where Databricks manages the compute and the storage.
There is no VPC to size, no IAM role to wire up, and no cross-account trust to configure.
You turn on a preview, fill in a short dialog, and the workspace comes up ready to use.
Start here for your first workspace and for most new deployments.

## Prerequisites

- A Databricks account with account-admin privileges.
- An AWS region where serverless workspaces are available. Deploy the workspace close to your data sources.

## Deploy with Terraform

You can create the same workspace as code.
A serverless workspace needs no IAM role, root bucket, or VPC, so the workspace resource is the only thing to declare.
Setting `compute_mode = "SERVERLESS"` is what makes it serverless.

```hcl title="main.tf"
terraform {
  required_providers {
    databricks = {
      source = "databricks/databricks"
    }
  }
}

variable "databricks_account_id" {
  description = "Account ID from the account console (top right, under your user name)"
}

provider "databricks" {
  host       = "https://accounts.cloud.databricks.com"
  account_id = var.databricks_account_id
}

resource "databricks_mws_workspaces" "this" {
  account_id     = var.databricks_account_id
  workspace_name = "serverless-workspace"
  aws_region     = "us-east-1"
  compute_mode   = "SERVERLESS"
}

output "workspace_url" {
  value = databricks_mws_workspaces.this.workspace_url
}
```

The provider talks to the account console, not a workspace.
Authenticate with an account-level service principal by exporting `DATABRICKS_CLIENT_ID` and `DATABRICKS_CLIENT_SECRET` before you run Terraform.
See [provider authentication](https://registry.terraform.io/providers/databricks/databricks/latest/docs#authentication) for other options.

Then run:

```bash
terraform init
terraform plan -var="databricks_account_id=<your-account-id>"
terraform apply -var="databricks_account_id=<your-account-id>"
```

When the apply finishes, Terraform prints `workspace_url`.
Open it and you land on the same **Welcome to Databricks** page shown above.

## Where people trip

<details>
<summary>Terraform rejects credentials_id or storage_configuration_id</summary>

Serverless workspaces must not set `credentials_id` or `storage_configuration_id`.
Those belong to classic workspaces, where you bring your own IAM role and root bucket.
Remove both arguments and keep `compute_mode = "SERVERLESS"`.
</details>

<details>
<summary>Serverless Workspaces is not in the Previews list</summary>

The preview toggle only shows for account admins.
Confirm you have account-admin privileges on the account console.
If it is still missing, serverless workspaces may not be available yet in your account or region.
</details>

<details>
<summary>The Metastore dropdown is empty</summary>

The metastore is optional at creation time.
Leave it blank if no metastore exists in that region, then attach one later.
See [Set the metastore admin group](/docs/02-account-workspaces/metastore-admins/set-admin-group) for managing metastore ownership.
</details>

<details>
<summary>Picked the wrong region</summary>

A workspace cannot move regions once created.
Delete the workspace and create a new one in the correct region.
Deploy in the region that hosts your data sources to avoid cross-region egress fees.
</details>
