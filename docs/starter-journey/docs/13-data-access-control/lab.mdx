# Hands-on: Data Access Control

> **You'll** apply RBAC grants, a column mask, and an ABAC tag-driven policy to a sample table in **35 to 45 min**.
>
> **Prereqs:** [12. Data Access Control](/docs/12-data-access-control/), a SQL warehouse or serverless cluster, `CREATE SCHEMA` on `main`

Run all steps in a SQL editor. Steps 1-3 work on any supported DBR. Step 4 (ABAC) requires **DBR 16.4+ or serverless**.

## 1. Set up the sample table

Create the schema and table, then insert four employees across three regions.

```sql
CREATE SCHEMA IF NOT EXISTS main.lab_dac;

CREATE OR REPLACE TABLE main.lab_dac.employees (
  employee_id INT,
  name        STRING,
  region      STRING,
  ssn         STRING,
  salary      DOUBLE
);

INSERT INTO main.lab_dac.employees VALUES
  (1, 'Alice',  'EMEA', '123-45-6789', 95000.0),
  (2, 'Bob',    'AMER', '234-56-7890', 87000.0),
  (3, 'Carlos', 'APAC', '345-67-8901', 91000.0),
  (4, 'Diana',  'EMEA', '456-78-9012', 102000.0);
```

**Checkpoint:** `SELECT * FROM main.lab_dac.employees` returns 4 rows.

## 2. RBAC: grant read access

Grant the `analysts` group the minimum privileges needed to read the table.

```sql
GRANT USE CATALOG ON CATALOG main                    TO `analysts`;
GRANT USE SCHEMA  ON SCHEMA  main.lab_dac            TO `analysts`;
GRANT SELECT      ON TABLE   main.lab_dac.employees  TO `analysts`;
```

Verify the grants were written correctly.

```sql
SHOW GRANTS ON TABLE main.lab_dac.employees;
```

**Checkpoint:** The output shows `SELECT` on `main.lab_dac.employees` granted to `analysts`.

## 3. Mask the SSN column

Create a UDF that shows real SSNs only to `hr_admin`. All other users see a redacted placeholder.

```sql
CREATE OR REPLACE FUNCTION main.lab_dac.cls_ssn(ssn STRING)
RETURNS STRING
RETURN CASE
  WHEN is_account_group_member('hr_admin') THEN ssn
  ELSE 'XXX-XX-XXXX'
END;

ALTER TABLE main.lab_dac.employees
  ALTER COLUMN ssn SET MASK main.lab_dac.cls_ssn;
```

**Checkpoint:** An `analysts` user running `SELECT ssn FROM main.lab_dac.employees` sees `XXX-XX-XXXX` in every row. A user in `hr_admin` sees real values.

## 4. ABAC: tag-driven salary mask (optional, DBR 16.4+)

Apply a column mask to every `salary` column across the schema via a governed tag, with no per-table wiring.

```sql
-- Masking UDF
CREATE OR REPLACE FUNCTION main.lab_dac.abac_mask_salary(salary DOUBLE)
RETURNS DOUBLE
RETURN IF(is_account_group_member('hr_admin'), salary, NULL);

-- Security policy
CREATE OR REPLACE SECURITY POLICY main.lab_dac.salary_mask_policy
  COLUMN MASK main.lab_dac.abac_mask_salary;

-- Tag the schema
ALTER SCHEMA main.lab_dac SET TAGS ('sensitivity' = 'high');

-- Bind the policy to the schema via tag
ALTER SECURITY POLICY main.lab_dac.salary_mask_policy
  SET SCHEMA main.lab_dac FILTER TAG sensitivity = 'high'
  ON COLUMN salary;
```

**Checkpoint:** Create a second table in `main.lab_dac` with a `salary` column. Without any `SET MASK` call, an `analysts` user sees `NULL` for salary. A user in `hr_admin` sees real values.

## 5. Clean up

Remove all access-control objects and the test schema.

```sql
-- Remove the column mask
ALTER TABLE main.lab_dac.employees ALTER COLUMN ssn DROP MASK;

-- Remove ABAC objects (if Step 4 was run)
DROP SECURITY POLICY IF EXISTS main.lab_dac.salary_mask_policy;

-- Drop UDFs, table, and schema
DROP FUNCTION IF EXISTS main.lab_dac.cls_ssn;
DROP FUNCTION IF EXISTS main.lab_dac.abac_mask_salary;
DROP TABLE   IF EXISTS main.lab_dac.employees;
DROP SCHEMA  IF EXISTS main.lab_dac;
```

**Checkpoint:** `SHOW SCHEMAS IN main` no longer lists `lab_dac`.
