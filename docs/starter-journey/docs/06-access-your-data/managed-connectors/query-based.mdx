# Query-based ingestion

> **You'll ingest** a database table incrementally with a cursor column in ~10 min.
>
> **Prereqs:** [Databases and SaaS ingestion](/docs/06-access-your-data/managed-connectors), [query-based connector requirements](https://docs.databricks.com/aws/en/ingestion/lakeflow-connect/query-based-pipeline#requirements)

## The big picture

A query-based connector runs a source query on the schedule you choose. After a successful run, it stores the highest cursor value it saw. The next run normally requests rows above that high-water mark and writes them to a Unity Catalog streaming table. With a timestamp cursor, SCD type 1 and type 2 also re-read a short window below the mark to catch late-arriving rows.

There is no gateway or staging volume. That makes the setup shorter, but the cursor has to be trustworthy. The connector cannot find an update if the cursor value does not change with the row.

The screenshots show a SQL Server setup. Other supported databases follow the same overall workflow, but source preparation, authentication methods, and available settings vary by connector. Follow the connection and source setup documentation for your database.

## Before you start

You need:

- A Unity Catalog-enabled workspace and a supported database reachable from serverless compute.
- Permission to create a Unity Catalog connection, or `USE CONNECTION` on an existing one.
- `USE CATALOG`, `USE SCHEMA`, and `CREATE TABLE` on the destination.
- A monotonically increasing timestamp or integer cursor column. SCD type 1 and type 2 also require a primary key.

Choose an authentication method supported by your database. The screenshots use a username and password.

<Step>

Select **Query based capture**. Name the pipeline and choose an event log catalog and schema. Select **Serverless**, then click **Create pipeline and continue**.

<StepImage src="/img/lakeflow-connect-query-based/4.png" alt="SQL Server ingestion setup with query based capture and serverless compute selected" />

<Step>

Enter the source database name and click the plus button.

<StepImage src="/img/lakeflow-connect-query-based/5.png" alt="Query-based source page with demo entered as the SQL Server database name" />

</Step>

<Step>

Expand the database and schema, then select the tables that you want to ingest. For each table, select one monotonically increasing timestamp or integer cursor column. If rows can change, the cursor must also change with each update. Configure a primary key and history tracking when required for the selected SCD mode, then click **Next**.

<StepImage src="/img/lakeflow-connect-query-based/6.png" alt="Customers selected with created_at as the cursor and customer_id as the primary key" />

</Step>

<Step>

Select the destination catalog and schema, then click **Save and continue**.

<StepImage src="/img/lakeflow-connect-query-based/7.png" alt="Query-based destination selection with the dev catalog and sql-server schema selected" />

</Step>

<Step>

On **Schedules and notifications**, create a refresh schedule and add notifications if needed. Click **Save and run pipeline**.

</Step>

</StepGuide>

## Where people trip

<details>
<summary>Updates never arrive</summary>

Check whether the cursor changes when a source row changes. A creation timestamp or auto-incrementing ID only tracks inserts unless the source also updates that value. Choose a cursor that advances whenever a source row changes.
</details>

<details>
<summary>Rows with a null cursor are missing</summary>

The connector does not ingest rows whose cursor value is `NULL`. Fix the source values or choose a cursor column that every row populates.
</details>

<details>
<summary>The pipeline cannot reach the source database</summary>

Query-based connectors require network connectivity from serverless compute to the database. Configure serverless network connectivity for the source hostname and port.
</details>

<details>
<summary>The source database is under unexpected load</summary>

Every pipeline update queries source tables directly. Check the schedule and add a B-tree index on the cursor column. If frequent queries put too much load on the source, consider a CDC connector.
</details>
