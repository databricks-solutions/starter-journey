# Files

> **You'll deploy** a serverless Lakeflow Connect pipeline that ingests files from a SaaS file repository into Unity Catalog, defined with DABs, in ~10 min.
>
> **Prereqs:** [Lakeflow Connect ingestion overview](/docs/06-access-your-data/managed-connectors), and the Databricks CLI installed and configured

## What you'll build

A serverless ingestion pipeline that pulls files from a document repository into Unity Catalog. File connectors share the SaaS pattern: no gateway, credentials in a UC connection, a serverless pipeline that names the connection and the files to land.

Reach for a file connector when the documents live in a SaaS repository like SharePoint or Google Drive. If the files already sit on cloud object storage (S3, ADLS, GCS), use Auto Loader instead, covered in [Build the first ETL pipeline](/docs/07-build-first-pipeline).

## What changes for your source

Same pattern, different auth and source addressing.

| Source | Auth | What you point at |
|---|---|---|
| SharePoint | OAuth (browser sign-in) | A site and document library. |
| Google Drive | OAuth (browser sign-in) | A shared drive or folder. |
| SFTP | Key or password | A host, path, and credentials. |

:::warning
SharePoint and Google Drive use OAuth, so create their connections in the UI, the sign-in needs a browser. SFTP uses a key or password, so its connection can be created from the CLI or a DABs resource.
:::

## Steps

<StepGuide
  description="Create the source connection, define the ingestion pipeline as DABs YAML, then deploy and run it."
  minutes={10}
  referenceHref="https://docs.databricks.com/aws/en/ingestion/lakeflow-connect"
  referenceLabel="Lakeflow Connect (Databricks docs)">

<Step>

Create the UC connection that holds the source credentials.

For SharePoint and Google Drive, do this in the UI: **Catalog** > **Connect** > **Connections** > **Create connection**, pick the source, and complete the browser sign-in. Grant the connector the OAuth scopes it needs to read the target site or folder. Confirm the connection reports `READY` before you deploy.

For SFTP, create the connection from the CLI with the host and key or password.

</Step>

<Step>

Define the ingestion pipeline in your DABs YAML. The pipeline names the connection and the source objects (the document library or folder) to land.

```yaml
variables:
  catalog:
    default: development

resources:
  pipelines:
    sharepoint_ingestion:
      name: sharepoint_to_uc
      ingestion_definition:
        connection_name: my_sharepoint_connection
        objects:
          - table:
              source_schema: <site-or-library>
              source_table: <document-set>
              destination_catalog: ${var.catalog}
              destination_schema: sharepoint_raw
```

Replace the `source_schema` and `source_table` placeholders with the site, library, or folder you are ingesting from.

</Step>

<Step>

Deploy the pipeline.

```bash
databricks bundle deploy
```

</Step>

<Step>

Start the pipeline.

```bash
databricks bundle run sharepoint_ingestion
```

Schedule it with a Jobs `pipeline_task` to keep the tables fresh, since Lakeflow Connect runs on demand rather than continuously.

</Step>

</StepGuide>

## Verify

<StepGuide eyebrow="Verify" idPrefix="verify">

<Step>

In the Databricks workspace, go to **Jobs & Pipelines** and confirm the pipeline shows a **Completed** status.

</Step>

<Step>

Go to **Catalog** > the target catalog and schema. Confirm the ingested tables appear with the file content and metadata.

</Step>

</StepGuide>

## Where people trip

<details>
<summary>OAuth connection stuck in PENDING</summary>

The browser sign-in was not completed, or the granted scopes do not cover the target site or folder. Re-open the connection in Catalog Explorer, finish the flow, and confirm the scopes include read access to the source.
</details>

<details>
<summary>Pipeline runs but lands no files</summary>

The connection's account cannot see the target library or folder. Confirm the account has been shared into the SharePoint site or Drive folder, then check the pipeline event log for pre-flight errors.
</details>
