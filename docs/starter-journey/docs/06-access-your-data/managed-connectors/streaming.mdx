# Streams

> **You'll deploy** a streaming ingestion pipeline that reads from a message bus into a Unity Catalog table, defined with DABs, in ~15 min.
>
> **Prereqs:** [Lakeflow Connect ingestion overview](/docs/06-access-your-data/managed-connectors), and the Databricks CLI installed and configured

## What you'll build

A pipeline that continuously reads events from a message bus (Kafka, Kinesis, Pub/Sub, Event Hubs) and appends them to a Unity Catalog table.

Streaming is the one source type that does **not** use a managed Lakeflow Connect connector. There is no connection object and no `ingestion_definition`. Instead you read the stream with Structured Streaming inside a Lakeflow Declarative Pipeline, which handles the checkpointing, exactly-once delivery, and incremental processing for you. You still define it as code with DABs, so the shape is familiar.

## What changes for your source

The pipeline structure is the same. What changes is the `format` and its connection options in the read.

| Source | `format` | Key options |
|---|---|---|
| Apache Kafka | `kafka` | `kafka.bootstrap.servers`, `subscribe` (topic), auth settings |
| Amazon Kinesis | `kinesis` | `streamName`, `region`, credentials |
| Google Pub/Sub | `pubsub` | `subscriptionId`, `topicId`, `projectId` |
| Azure Event Hubs | `kafka` | Event Hubs Kafka endpoint as `bootstrap.servers` |

## Steps

<StepGuide
  description="Write the streaming read as a pipeline source file, define the pipeline as DABs YAML, then deploy and run it."
  minutes={15}
  referenceHref="https://docs.databricks.com/aws/en/structured-streaming"
  referenceLabel="Structured Streaming (Databricks docs)">

<Step>

Write the streaming read as a pipeline source file. This one reads a Kafka topic and appends it to a streaming table. For another source, change the `format` and its options per the table above.

```python
import dlt

@dlt.table(name="events_raw")
def events_raw():
    return (
        spark.readStream
        .format("kafka")
        .option("kafka.bootstrap.servers", "<broker-host>:9092")
        .option("subscribe", "<topic>")
        .option("startingOffsets", "latest")
        .load()
    )
```

</Step>

<Step>

Define the pipeline in your DABs YAML, pointing at the source file. This is a standard declarative pipeline (a `libraries` block), not a managed-connector `ingestion_definition`.

```yaml
variables:
  catalog:
    default: development

resources:
  pipelines:
    streaming_ingestion:
      name: streaming_to_uc
      catalog: ${var.catalog}
      target: streaming_raw
      libraries:
        - file:
            path: ./src/events_raw.py
```

</Step>

<Step>

Store the source credentials as secrets rather than in the source file. Reference them in the read with `dbutils.secrets.get(...)` so the broker password never lands in version control.

</Step>

<Step>

Deploy and start the pipeline.

```bash
databricks bundle deploy
databricks bundle run streaming_ingestion
```

</Step>

</StepGuide>

## Where people trip

<details>
<summary>Pipeline starts but no events arrive</summary>

Check the broker address, topic name, and `startingOffsets`. With `latest`, only events produced after the pipeline started are read; use `earliest` to backfill from the start of the retained log.
</details>

<details>
<summary>Authentication fails against the broker</summary>

Confirm the auth options match the broker's mechanism (SASL, TLS) and that the secret values are correct. Pull credentials from a secret scope, not from plain text in the source file.
</details>

<details>
<summary>The message bus is not reachable</summary>

Streaming compute needs a network path to the broker. Check security-group rules and firewall settings, and for a private broker, confirm the workspace has private connectivity to it.
</details>
