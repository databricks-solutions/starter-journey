# Lakeflow Connect ingestion

> **You'll understand** how Lakeflow Connect ingestion pipelines work and pick the right setup pattern for your source in ~5 min.
>
> **Prereqs:** [Access your data](/docs/06-access-your-data)

## The big picture

A **connection** lets Databricks reach an external system. An **ingestion pipeline** puts it to work: it replicates data into Unity Catalog tables, change data capture (CDC) included, and keeps them current. No pipeline, and the connection just sits there while your data stays in the source.

Lakeflow Connect gives you managed connectors for that job. You store the source credentials once in a UC connection, point a pipeline at it, and Databricks handles retries, schema evolution, and incremental loading. The output is a governed Delta table you can build on.

## The one fork that matters

Every connector sets up the same way except for one split. Get this right and the rest follows:

- **Serverless connectors.** SaaS apps and files (Salesforce, ServiceNow, SharePoint, and so on) run entirely on serverless compute. You create a connection, define a pipeline, run it. No infrastructure to place.
- **Gateway connectors.** Databases (SQL Server, PostgreSQL, MySQL, Oracle) need an **ingestion gateway** running on classic compute inside your own network, because that is what can reach the source and read its change feed. The gateway stages changes; a serverless pipeline then applies them to Delta.

So the real question is not "which brand" but "does my source need a gateway?"

## Which page do I need?

Match your source to a setup pattern, then follow that page. All four lead with the Databricks Asset Bundles (DABs) definition so the pipeline is version-controlled and repeatable.

| Your source | Setup pattern | Gateway? | Page |
|---|---|---|---|
| SQL Server, PostgreSQL, MySQL, Oracle | Database CDC | Yes, classic compute | [Databases](/docs/06-access-your-data/managed-connectors/databases) |
| Salesforce, Workday, ServiceNow, Google Analytics, HubSpot, Confluence | SaaS pull | No, serverless | [SaaS apps](/docs/06-access-your-data/managed-connectors/saas) |
| SharePoint, Google Drive, SFTP | File pull | No, serverless | [Files](/docs/06-access-your-data/managed-connectors/files) |
| Kafka, Kinesis, Pub/Sub, Event Hubs | Structured Streaming | No, serverless | [Streams](/docs/06-access-your-data/managed-connectors/streaming) |

Streaming sources are the odd one out: they are not managed Lakeflow Connect connectors. You ingest them with Structured Streaming instead. The [Streams](/docs/06-access-your-data/managed-connectors/streaming) page shows how.
