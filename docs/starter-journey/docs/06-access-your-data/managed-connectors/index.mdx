# Databases and SaaS ingestion

> **You'll choose** a managed ingestion pattern and know what each one requires in ~5 min.
>
> **Prereqs:** [Access your data](/docs/06-access-your-data)

## The big picture

Lakeflow Connect copies data from an external database or SaaS application into Unity Catalog streaming tables. The source credentials live in a Unity Catalog connection. The ingestion pattern decides how Databricks finds new and changed rows.

For databases, start with this choice:

| Compare | Query-based connectors | CDC database connectors |
|---|---|---|
| Gateway | No ingestion gateway | Uses an ingestion gateway for the standard CDC architecture |
| Staging | No staging volume | Stages captured changes in a Unity Catalog volume |
| Ingestion timing | Runs on a schedule | Captures source changes continuously, then applies them on the ingestion pipeline schedule |
| Change history | Reads the latest row state available to each query. It does not capture intermediate states between runs | Captures intermediate changes recorded by the source change log |
| Source compatibility | Works with a broader set of database sources, including sources without CDC support | Requires a supported CDC source and source-side CDC configuration |
| Source impact | Queries source tables directly, which adds source load and can result in slower queries | Reads the source change log instead of repeatedly querying source tables |

## Supported database sources

CDC connectors are available for MySQL, PostgreSQL, SQL Server, and Oracle. Direct query-based connections support Oracle, Teradata, SQL Server, MySQL, MariaDB, and PostgreSQL. Query-based ingestion through a foreign catalog supports Lakehouse Federation data sources.

The screenshots in both walkthroughs show SQL Server. Other supported database connectors follow the same overall workspace workflow. Source preparation, authentication methods, and available settings vary by connector, so check the documentation for your database before you start. The CDC walkthrough uses the standard gateway-based architecture. SQL Server also supports integrated CDC with a single pipeline, which is outside this walkthrough.

## Build an ingestion pipeline

- **[Change data capture (CDC)](/docs/06-access-your-data/managed-connectors/cdc):** create a database connection, gateway, and ingestion pipeline, then validate the source and select tables to ingest.
- **[Query-based ingestion](/docs/06-access-your-data/managed-connectors/query-based):** query a database incrementally with a cursor column and load the result into Unity Catalog.
