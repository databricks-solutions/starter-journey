# GCP GCS

> **You'll create** a storage credential and external location to connect Databricks to GCS in ~10 min.
>
> **Prereqs:** [Cloud Object Storage overview](/docs/06-access-your-data/cloud-object-storage), GCP project with Owner permissions

## What you'll build

A Google Cloud Storage bucket Databricks can read through a Unity Catalog storage credential and external location.

## Prerequisites

- A GCP project with Owner or Storage Admin permissions.
- A Databricks workspace with metastore-admin or account-admin privileges.

## Steps

<StepGuide
  description="GCS setup is fully covered by the official Databricks guide, so this page hands you off, then has you mark the external location read-only."
  minutes={10}
  referenceHref="https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/external-locations-gcs"
  referenceLabel="GCS external locations (Databricks docs)">

<Step>

Follow the official guide: [Connect to a Google Cloud Storage (GCS) external location](https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/external-locations-gcs). It creates a service account, grants it access to your bucket, registers the storage credential, and creates the external location.

</Step>

<Step>

Mark the external location as read-only. Once it exists, set it to read-only so no Databricks workload can write to that path and a stray job cannot clobber your source data. Follow the guide: [Mark an external location as read-only](https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/manage-external-locations#mark-an-external-location-as-read-only).

:::warning
Skip this and the location stays writable for any principal with write grants. Leave it read-only unless a pipeline genuinely needs to write back to this path.
:::

</Step>

</StepGuide>

## Verify

<StepGuide eyebrow="Verify" idPrefix="verify">

<Step>

In the Databricks workspace, navigate to **Catalog** > **External Data** > **External Locations**.

</Step>

<Step>

Click the new external location and click **Test Connection**.

</Step>

<Step>

Confirm the test returns a success status.

</Step>

</StepGuide>

## Where people trip

<details>
<summary>Test Connection fails with permission denied</summary>

The service account behind the storage credential needs the `storage.objectAdmin` role (or equivalent) on the target bucket. Grant it and test again.
</details>

<details>
<summary>Storage credential creation fails</summary>

Check the service account key or workload identity federation setup. The service account has to live in the same GCP project as the Databricks workspace.
</details>
