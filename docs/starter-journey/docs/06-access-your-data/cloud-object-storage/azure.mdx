# Azure ADLS

> **You'll create** an access connector, storage credential, storage account, and external location to connect Databricks to ADLS Gen2 in ~25 min.
>
> **Prereqs:** [Cloud Object Storage overview](/docs/06-access-your-data/cloud-object-storage), Azure subscription with Contributor permissions

## The big picture

An ADLS Gen2 storage account Databricks can reach, wired up through an access connector, a Unity Catalog storage credential, and one or more external locations. Azure has the most moving parts of the three clouds, so expect a few more steps here.

## Prerequisites

- An Azure subscription with Contributor permissions.
- A Databricks workspace with metastore-admin or account-admin privileges.
- The storage account must have **hierarchical namespace enabled** (ADLS Gen2).

## Steps

### 1. Create an access connector

<StepGuide
  description="The access connector is the managed identity Databricks uses to authenticate to your storage account. Create it first; everything else points back to it."
  idPrefix="connector">

<Step>

In the [Azure portal](https://portal.azure.com/), search for **Access Connector for Azure Databricks** and select it.

<StepImage src="/img/azure/azure_access_connector_searchbar.png" placeholder="Azure Access Connector search" />

</Step>

<Step>

Click **Create**.

<StepImage src="/img/azure/create_access_connector_buttom.png" placeholder="Create Access Connector button" />

</Step>

<Step>

Fill in the form:

- **Subscription:** the subscription where the connector will be deployed.
- **Resource group:** choose or create a resource group.
- **Name:** a descriptive name for the connector.
- **Region:** same region as your Databricks workspace.

</Step>

<Step>

Click **Review + create**, then **Create**.

<StepImage src="/img/azure/access_connector_name.png" placeholder="Access Connector configuration form" />

<StepImage src="/img/azure/access_connector_create_buttom.png" placeholder="Access Connector create confirmation" />

</Step>

<Step>

After deployment, navigate to the new access connector and copy the **Resource ID** from the overview page.

<StepImage src="/img/azure/copy_ac_resource_id.png" placeholder="Copy Access Connector Resource ID" />

</Step>

</StepGuide>

### 2. Create a storage credential in Databricks

<StepGuide idPrefix="credential">

<Step>

In the Databricks workspace, click **Catalog** in the left sidebar.

<StepImage src="/img/azure/ws_catalog_buttom.png" placeholder="Databricks Catalog menu" />

</Step>

<Step>

Click **External Data**.

<StepImage src="/img/azure/external_location_buttom.png" placeholder="External Data menu" />

</Step>

<Step>

Go to the **Credentials** tab and click **Create credential**.

<StepImage src="/img/azure/create_credential_buttom.png" placeholder="Create Credential button" />

</Step>

<Step>

Fill in the form:

- **Credential Name:** a descriptive name.
- **Authentication Type:** Azure Managed Identity.
- **Access Connector ID:** paste the Resource ID from Step 1.
- **Description:** optional.

</Step>

<Step>

Click **Create**.

</Step>

</StepGuide>

### 3. Create or prepare a storage account

If you already have a compliant ADLS Gen2 storage account, skip to Step 4.

<StepGuide idPrefix="storage">

<Step>

In the [Azure portal](https://portal.azure.com/), search for **Storage Account** and select it.

</Step>

<Step>

Click **Create**.

<StepImage src="/img/azure/storage_account_create.png" placeholder="Create Storage Account" />

</Step>

<Step>

Configure the **Basics** tab:

- **Subscription:** same as your Databricks workspace.
- **Resource group:** same as or adjacent to your workspace resources.
- **Storage account name:** globally unique, lowercase letters and numbers only.
- **Region:** same region as your Databricks workspace.
- **Performance:** Standard (sufficient for most use cases).
- **Redundancy:** choose based on durability requirements (LRS, ZRS, GRS, or GZRS).

<StepImage src="/img/azure/storage_account_project_details.png" placeholder="Storage Account project details" />

</Step>

<Step>

In the **Advanced** tab, enable **Hierarchical namespace** (required for Unity Catalog). Set access tier to Hot.

:::warning
Hierarchical namespace must be enabled at creation time. It cannot be enabled on an existing storage account.
:::

<StepImage src="/img/azure/storage_account_advanced_settings.png" placeholder="Storage Account advanced settings" />

</Step>

<Step>

Click **Review + create**, then **Create**.

</Step>

<Step>

Navigate to the new storage account, create a **container**, and optionally add directories inside it (e.g., `bronze`, `silver`, `gold`).

<StepImage src="/img/azure/create_container_journey.png" placeholder="Create container in storage account" />

<StepImage src="/img/azure/folder_journey.png" placeholder="Add directory inside container" />

</Step>

</StepGuide>

### 4. Assign IAM permissions to the access connector

The connector's managed identity has no access to the storage account yet. Grant it the **Storage Blob Data Contributor** role, or the Test Connection in Step 6 will fail.

<StepGuide idPrefix="iam">

<Step>

In the Azure portal, navigate to the storage account.

</Step>

<Step>

Click **Access control (IAM)** in the left sidebar.

</Step>

<Step>

Click **+ Add** > **Add role assignment**.

<StepImage src="/img/azure/access_control_iam.png" placeholder="Storage Account IAM" />

</Step>

<Step>

Search for **Storage Blob Data Contributor**, select it, and click **Next**.

<StepImage src="/img/azure/blob_contributor.png" placeholder="Storage Blob Data Contributor role" />

</Step>

<Step>

In the **Members** section:

- Select **Managed identity** as the assignment type.
- Click **+ Select members** and search for your access connector.
- Select it, click **Select**, then **Review + assign**.

<StepImage src="/img/azure/add_member.png" placeholder="Add managed identity to role assignment" />

</Step>

</StepGuide>

### 5. Create an external location in Databricks

<StepGuide idPrefix="extloc">

<Step>

In the Databricks workspace, go to **Catalog** > **External Data**.

<StepImage src="/img/azure/external_location_buttom.png" placeholder="External Data menu" />

</Step>

<Step>

Go to the **External Locations** tab and click **Create external location**.

<StepImage src="/img/azure/create_external_location_buttom.png" placeholder="Create external location button" />

</Step>

<Step>

Fill in the form:

- **External Location Name:** a descriptive name (e.g., `raw-data-location`).
- **Storage Type:** Azure Data Lake Storage Gen2.
- **URL:** `abfss://<container>@<storage_account>.dfs.core.windows.net/<folder_path>`
- **Storage credential:** select the credential from Step 2.

</Step>

<Step>

Click **Create**.

<StepImage src="/img/azure/external_location_form.png" placeholder="External location creation form" />

</Step>

</StepGuide>

### 6. Mark the external location as read-only

<StepGuide idPrefix="readonly">

<Step>

Once the external location exists, set it to read-only. Now no Databricks workload can write to that path, so a stray job cannot clobber your source data. Follow the guide: [Mark an external location as read-only](https://learn.microsoft.com/en-us/azure/databricks/connect/unity-catalog/cloud-storage/manage-external-locations#mark-an-external-location-as-read-only).

:::warning
Skip this and the location stays writable for any principal with write grants. Leave it read-only unless a pipeline genuinely needs to write back to this path.
:::

</Step>

</StepGuide>

## Verify

<StepGuide eyebrow="Verify" idPrefix="verify">

<Step>

In the Databricks workspace, navigate to **Catalog** > **External Data** > **External Locations**.

</Step>

<Step>

Click the new external location and click **Test Connection**.

<StepImage src="/img/azure/test_connection.png" placeholder="Test Connection button" />

</Step>

<Step>

Confirm the test returns a success status.

</Step>

</StepGuide>

## Where people trip

<details>
<summary>Test Connection fails with permission denied</summary>

The connector's managed identity is missing the Storage Blob Data Contributor role. Check the role assignment under the storage account's Access control (IAM) section in the Azure portal. This is Step 4, and it is the most common one to skip.
</details>

<details>
<summary>External location creation fails with invalid URL</summary>

The URL has to be `abfss://<container>@<storage_account>.dfs.core.windows.net/<path>`. Confirm the container exists, the storage account name is right, and hierarchical namespace is on.
</details>

<details>
<summary>Storage credential creation fails</summary>

Recopy the Access Connector Resource ID from the Azure portal overview page; a truncated paste is the usual cause. The connector also has to be in the same region as the workspace.
</details>
