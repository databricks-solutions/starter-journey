# Azure ADLS

> **You'll create** an access connector, storage account, container, storage credential, IAM role assignment, external location, and network connectivity configuration to connect Databricks to ADLS Gen2 in ~30 min.
>
> **Prereqs:** [Cloud Object Storage overview](/docs/06-access-your-data/cloud-object-storage), Azure and Unity Catalog privileges listed below

## The big picture

You want an ADLS Gen2 storage account Databricks can reach, wired up through an access connector, a Unity Catalog storage credential, and an external location. Azure has the most moving parts of the three clouds, so there are a few more steps here. If your workspace uses serverless private networking, the last part attaches a network connectivity configuration so serverless compute can reach the storage account over a private endpoint.

## Permissions you need

Check these before you start. A missing Azure role is why Create is greyed out in the portal. A missing Unity Catalog privilege is why the storage credential or external location never saves.

The storage account must have **hierarchical namespace** enabled (ADLS Gen2). That option is only available at create time.

### Azure

Assign these Azure RBAC roles on the resource group (or subscription) that will hold the access connector and storage account:

| Role | Why you need it |
|---|---|
| **Storage Account Contributor** or **Contributor** | Create the storage account. Change its **Networking** settings: public network access, firewall, VNet rules, and private endpoints. |
| **User Access Administrator** or **Owner** | Assign **Storage Blob Data Contributor** to the access connector. Contributor cannot grant Azure roles. |
| **Network Contributor** | Create private endpoints and attach them to a virtual network. Skip this if you leave public access on for this walkthrough. |

Contributor on the resource group covers creating the storage account and editing its network settings. It does **not** let you assign IAM roles. If you cannot open **Access control (IAM)** > **Add role assignment**, you are missing User Access Administrator or Owner.

### Azure Databricks

You need these Unity Catalog privileges. Metastore admins and account admins already have them. Workspace admin is not enough on its own.

| Privilege | On | Why you need it |
|---|---|---|
| `CREATE STORAGE CREDENTIAL` | Metastore | Create the credential that wraps the access connector. |
| `CREATE EXTERNAL LOCATION` | Metastore | Create the path object. |
| `CREATE` | The storage credential | Bind that credential to an external location. |

If you are not a metastore admin, ask one to grant your group:

```sql
GRANT CREATE STORAGE CREDENTIAL, CREATE EXTERNAL LOCATION ON METASTORE TO `your-group`;
```

Creating a network connectivity configuration in the account console also needs **account admin**.

## Create an access connector

The access connector is the managed identity Databricks uses to authenticate to your storage account. Create it first, because everything else points back to it.

  referenceLabel="Connect to ADLS Gen2 using Unity Catalog (Databricks docs)">

<Step>

In the [Azure portal](https://portal.azure.com/), search for **Access Connector for Azure Databricks** and select it.

- **Subscription:** the subscription where the connector will be deployed.
- **Resource group:** choose or create a resource group (for example `starter-journey`).
- **Name:** a descriptive name (for example `starter-journey-ac`).
- **Region:** the same region as your Databricks workspace.

<StepImage src="/img/azure/object_storage_external_location/03_access_connector_fill.png" alt="Access connector Basics tab with subscription, resource group, name, and region" />

## Create a storage account

If you already have a compliant ADLS Gen2 storage account, skip to [Create a container](#create-a-container).

<StepGuide
  description="Create an ADLS Gen2 storage account with hierarchical namespace enabled."
  minutes={5}
  idPrefix="storage-account-step"
  referenceHref="https://learn.microsoft.com/en-us/azure/storage/blobs/create-data-lake-storage-account"
  referenceLabel="Create an ADLS Gen2 storage account (Azure docs)">

<Step>

In the Azure portal, search for **Storage account** and select it.

<StepImage src="/img/azure/object_storage_external_location/06_stg_searchbar.png" alt="Search the Azure portal for Storage account" />

</Step>

<Step>

Click **Create**.

<StepImage src="/img/azure/object_storage_external_location/07_stg_creation.png" alt="Create button on the Storage accounts listing" />

</Step>

<Step>

Fill in the **Basics** tab:
- **Subscription:** the same subscription as your Databricks workspace.
- **Resource group:** the same resource group as your workspace resources.
- **Storage account name:** globally unique, lowercase letters and numbers only.
- **Region:** the same region as your Databricks workspace.
- **Primary service:** Azure Blob Storage or Azure Data Lake Storage Gen2.
- **Performance:** Standard is enough for most cases.
- **Redundancy:** choose based on your durability needs (LRS, ZRS, GRS, or GZRS).

<StepImage src="/img/azure/object_storage_external_location/08_stg_create_step1.png" alt="Storage account Basics tab" />

</Step>

<Step>

On the **Advanced** tab, check **Enable hierarchical namespace** and set the access tier to **Hot**.

:::warning
Hierarchical namespace has to be enabled at creation time. You cannot turn it on for an existing storage account.
:::

<StepImage src="/img/azure/object_storage_external_location/09_stg_create_step2.png" alt="Storage account Advanced tab with hierarchical namespace enabled" />

</Step>

<Step>

Click **Review + create**, then **Create**.

<StepImage src="/img/azure/object_storage_external_location/10_stg_create_step3.png" alt="Storage account Review + create tab" />

</Step>

<Step>

When the deployment finishes, click **Go to resource** to open the new storage account.

<StepImage src="/img/azure/object_storage_external_location/11_stg_create_step4.png" alt="Storage account deployment complete" />

</StepGuide>

## Configure network connectivity (NCC)

You only need this part when the storage account is set to private, meaning it is not open to the public internet. In that case, serverless compute cannot reach it over the network by default, so you attach a network connectivity configuration that gives serverless an Azure Private Link endpoint to read and write the storage account. If the storage account allows public network access, skip this part.

<StepGuide
  description="Create a network connectivity configuration, add private endpoint rules, approve them, and attach the NCC to your workspace."
  minutes={8}
  idPrefix="ncc-step"
  referenceHref="https://learn.microsoft.com/en-us/azure/databricks/security/network/serverless-network-security/serverless-private-link"
  referenceLabel="Configure private connectivity to Azure resources (Databricks docs)">

<Step>

In the [account console](https://accounts.azuredatabricks.net/), open **Security**.

## Connect classic compute to the storage account

Like the NCC, this part is only needed when the storage account is private. The NCC covers serverless compute. Classic compute (clusters that run inside your workspace's virtual network) reaches a private storage account through a private endpoint you create on the storage account into that virtual network. Create two, one for the `dfs` subresource and one for `blob`.

## Where people trip

<details>
<summary>Test Connection fails with permission denied</summary>

The connector's managed identity is missing the Storage Blob Data Contributor role. Check the role assignment under the storage account's Access control (IAM) section in the Azure portal. This is the [Grant IAM permissions](#grant-iam-permissions-to-the-access-connector) step, and it is the most common one to skip.
</details>

<details>
<summary>External location creation fails with invalid URL</summary>

The URL has to be `abfss://<container>@<storage_account>.dfs.core.windows.net/<directory>`. Confirm the container exists, the storage account name is right, and hierarchical namespace is on.
</details>

<details>
<summary>Storage credential creation fails</summary>

Recopy the access connector Resource ID from the Azure portal overview page. A truncated paste is the usual cause. The connector also has to be in the same region as the workspace.
</details>

<details>
<summary>Hierarchical namespace is not available on the storage account</summary>

Hierarchical namespace can only be enabled when the storage account is created. Create a new storage account with the option checked and repeat the steps against it.
</details>

<details>
<summary>Private endpoint stays in Pending</summary>

A serverless private endpoint rule is not active until you approve the connection on the storage account. Open the storage account's Networking > Private endpoint connections tab in the Azure portal and approve the pending request.
</details>
